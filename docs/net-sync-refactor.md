# 联网同步架构 v3

> 状态：已实现，协议版本为 2，不保留旧中继协议兼容代码。

## 为什么重构

旧方案由房主浏览器运行权威逻辑。加入者的输入经过网络后，房主会把同一批输入合并成一次移动，却把最后一个序号作为已执行回执；加入者再按估算的半个往返时间纠偏。这会造成持续前进时画面先前进、再后退、再前进，开火按下沿也可能在输入合并时丢失。

新方案采用常见实时网游的基本结构：服务器权威、客户端预测、输入确认后纠偏、远端插值和射击延迟补偿。实现规模保持精简，没有加入账号、排行、自动匹配或数据库。

参考原则：Valve Source Multiplayer Networking 的客户端预测、实体插值和延迟补偿，以及 Unreal Engine Networked Movement 的未确认移动保存与重放。

## 运行结构

```text
浏览器 P1 ── 输入批次 ──┐
                         ├─> 通用实时对局内核 ─> 坦克适配器 ─> World
浏览器 P2 ── 输入批次 ──┘          │                   │
                                   └──── 30Hz 快照 ─────┘
```

### 通用实时对局内核

`server/runtime/realtime-service.js` 不引用任何坦克实体，负责房间与席位、输入队列、60Hz 固定帧、30Hz 快照、断线恢复和空闲清理。

其他实时游戏可以注册自己的 `GameDefinition`，实现 `validateInput` 和 `createMatch`，再由 Match 实现输入、逻辑帧、快照、阶段与玩家移除接口。通用层不包含账号、排行、持久化或自动匹配。

### 坦克游戏适配器

`server/games/tank-match.js` 创建并驱动真实 `World`，管理 `intro / playing / tally / over` 阶段，把席位输入转换为 `Player.applyControl`，并提供音效事件、开火结果和权威快照。

## 输入、预测与纠偏

- 浏览器每逻辑帧生成连续 `seq`，每 2 帧批量发送。序号跨关卡延续（战斗会话随场景销毁时由控制器接住序号），整场对局单调递增，与服务端席位序号对齐；只有断线恢复时两端才一起归零。
- 服务端按序逐条执行，每个服务端帧最多追赶 4 条，并用服务端产生的执行额度限制平均移动速度。
- 开幕/结算/结束等非战斗阶段不消费输入，并清空滞留队列，防止上一阶段的旧输入在下一阶段开头"漂移"执行。
- 快照中的 `ack` 只表示已经执行完成的最后一个输入，不表示“已经收到”。
- 客户端保存每个 `seq` 的输入和预测结果。预测结果与权威位置一致时不改位置；只有真正不一致时，才恢复权威状态并重放 `ack` 之后的输入。
- 不再使用半个往返时间估算，也不再用画面偏移抵消错误纠偏。

## 开火与命中

- 开火与移动处于同一条输入命令，使用独立递增的 `fireSeq`（同样跨关卡延续）。
- 客户端按键当帧生成预测子弹和音效；预测子弹本地只检测地形与坦克遮挡，命中判定以服务端为准。
- 服务端为每个 `fireSeq` 返回一次明确的接受或拒绝结果，权威子弹按 `fireSeq` 接管预测子弹。
- 音效事件带玩家席位和 `fireSeq`，只去除自己的重复枪声，不会误删队友枪声。
- 服务端保存约 2 秒敌人位置历史，按客户端实际看到的服务端帧开始判定子弹轨迹。
- 暂停状态由服务端即时广播（不等下一份快照），双方客户端当帧同步停止/恢复预测。

## 快照与网络波动

- 服务端逻辑 60Hz，世界快照 30Hz。
- 客户端自己的坦克不插值；敌人、队友、权威子弹和道具按服务端帧插值。
- 插值缓冲基础为 4 帧，按到包波动在 4～10 帧内调整。
- 目标网络条件为约 250ms 往返延迟、约 60ms 波动。

## 断线恢复

- 房间码、席位和恢复令牌写入 `sessionStorage`，同一标签页刷新后会自动恢复。
- 短暂断线时服务端世界继续运行，不暂停另一名玩家。
- 30 秒内恢复原席位时，服务端增加 `epoch`、清空旧输入并立即发送完整快照。
- 超过 30 秒后该玩家从世界移除，恢复令牌作废，剩余玩家继续单人完成当前对局。

## 联机结束后重开

- 双方全灭或基地被毁后，房间保持存在，不需要重新创建房间码。
- 两位玩家在结束画面按 Enter 确认后，服务端保留当前关卡和分数，恢复双方命数并重新进入本关。
- 按 P 可以主动离开房间。

## 部署边界

正式部署只保留 Node / Docker / VPS。Cloudflare Worker 中继已经移除，因为现在服务端需要持续运行 60Hz 权威世界，不再是无状态消息转发。
